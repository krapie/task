# Task

Personal daily task board that combines recurring routines, one-off tasks, calendar events, email, and news into a single interface. Works offline in guest mode (localStorage) and syncs across devices when signed in. **Live:** [task.kevinprk.com](https://task.kevinprk.com)

## Getting Started

```bash
# Frontend
npm install
npm run dev   # http://localhost:5173, proxies /api → localhost:3000

# API (separate terminal)
node server/index.js
```

## Features

- **Tasks tab (the routine board)** — one list per day: Daily tasks, then Bonus, Tasks and today's Events as small labeled groups that only appear when they have items; a single add bar under the list switches between Daily / Bonus / Task. The list is left-aligned and at most 600px wide (full width on phones). It is sized for desktop windows from about 1000 × 680 up to 1280 × 710: the list scrolls inside while the add bar stays visible. Goals and Retro have their own tabs in the Tasks | Goals | Retro toggle. 6 day slots (Mon–Fri + Weekend) with recurring daily tasks that auto-reset at a configurable hour; drag to reorder; hide a routine for just the active day (it reappears at the next reset, is excluded from progress and the daily reminder, and can be restored from the collapsible "Hidden today" list)
- **Overview** — its own nav group, first in the rail (`#/overview`, `g o`; the old `#/today/overview` link still lands on it). It is the main page on every screen size (the app opens on it and the π mark returns to it); guests see the upper band only. On a phone the panels stack and scroll, listing five events and four mails (the panel title opens the whole tab). Two bands on one screen with the same three columns (their vertical hairlines line up), no page scroll, long lists scroll inside their panel; the lower band is as tall as its content and the upper band takes the rest. The owner can drag the line between the two bands on desktop (↑ / ↓ move it, double click or Home gives the automatic height back): the private band keeps the height you set, per browser, between 150 px and what leaves 260 px for the day band, and its panels scroll inside when it is smaller than their content (`Splitter.tsx`). **Upper:** **Today** (a ring of what is done, the day's schedule, routines, bonus and todos due or late as groups; groups without items are not drawn; Todos continue with up to five open todos due later or undated as suggestions that stay out of the ring; ticks write exactly like the Tasks board), **Upcoming events** (a 14-day density strip and the next 10 events with date tiles, recurring ones expanded; a click opens that day in Calendar) and **Inbox** (unread count, the latest ten; signed in). While Inbox has 0 unread mail the panel becomes **News** (the latest ten GeekNews stories, each opening its link; the title opens the News tab), and it goes back to Inbox as soon as mail arrives. **Lower, owner only and locked behind the passkey step-up:** **Health** (sleep first, because steps are biased by when the watch is worn: last night's hours with bedtime and wake time, the stage bar, a 14-night chart against the 7-day average, then the three activity rings, resting HR, HRV, VO₂ max and steps), **Assets** (net worth, income against spending this month, allocation, investments) and **Trader** (value, gain, the trader account's value chart, the ETF mix, the latest weekly buy); one *Show with passkey* opens all three, Hide masks them, Lock / backgrounding / the hour's end drop the fetched values, and the band requests nothing while locked. Today and Upcoming events are derived from the state the app already holds (`lib/overview.ts`); the Overview's own requests are the mail unread calls (5-minute refresh), `GET /api/news` (only while the inbox is empty) and, once unlocked, `GET /api/health-data/summary`, `/api/assets/summary` and `/api/trader/summary`. Narrow screens stack the panels and scroll
- **Trader** — owner-only tab under Life (`#/life/trader`), passkey step-up like Assets and Health: total value, gain, cash, day-trade net, the portfolio value chart (Banksalad value against cost), the ETFs with their share against target and a trend, and the weekly buys against the S&P 500 ETF. Read-only: `GET /api/trader/summary` (`stepUpAuth`, audit event `trader_view`, 60 s cache) fetches a summary from ops (`GET /internal/trader-summary`, its own token `TRADER_SUMMARY_TOKEN`; `docs/apps/trader.md`, "Task app")
- **Bonus tasks** — one-off task additions per day slot, separate from the recurring routine
- **Tasks** — global todo list with optional due dates shown alongside the routine board
- **Multi-day add** — add a daily task to multiple day slots at once from the quick-add input
- **Calendar** — monthly view with event management; supports weekly, monthly, and yearly recurring events
- **Goals** — three side-by-side columns of categorized goal lists: General (bucket list), Year, and Half (H1/H2 of the selected year), driven by a shared year selector with an add-year control. The Year column consolidates the selected year's half-year goals into its annual list by category name (shown read-only with an H1/H2 badge). Items support completion, strikethrough, and inline comments. Narrow screens collapse the columns into a General/Year/Half tab switcher
- **Mail** — IMAP inbox: add multiple accounts, read HTML email in a sandboxed iframe with dark mode, mark read/unread, mark all read. Syncs `INBOX` plus a `청구·결제` (bills/payments) folder where present, since some providers (Naver) auto-file statements there instead of INBOX. Sync runs in the background in mail-bridge, one at a time across all accounts in parallel (60s per-account timeout): every 5 minutes, on opening the Mail tab (skipped if the last sync finished under a minute ago), and on the Sync button (forced). `POST /api/mail/sync` (`{account_id?, force?}`) returns `202` at once; the UI polls `GET /api/mail/sync` until `running` is false
- **Mail Inbox / Others** — the sidebar splits mail into **Inbox** (general) and **Others** (promotions and anything you file there), each with its own unread badge; the Mail tab badge and push notifications count Inbox only. Flagged spans both. mail-bridge classifies at sync time into `mail_items.category` (`general` | `others`): Gmail accounts use Gmail's own Promotions tab (`X-GM-RAW category:promotions`; Social/Updates stay in Inbox), other providers use the Korean-law `(광고)` / `[광고]` subject prefix. The archive / inbox button on a row and in the conversation header moves a whole conversation between the two (`POST /api/mail/threads/move` `{account_id, thread_id, category}`); a manual move sticks, since sync classifies only new mail. After a move, a bar offers **Always move mail from <sender>**: that stores a sender rule in `mail_sender_rules` (address lower-cased) which beats the automatic classification for new mail and also moves the sender's existing mail; Accounts → Sender rules lists and removes them (removing a rule keeps mail where it is). API: `GET/PUT/DELETE /api/mail/sender-rules` (`PUT {from_address, category}` → `{moved}`; `DELETE ?from_address=`, in the query because of `@`/`+`). API: `GET /api/mail/threads?category=general|others`, `GET /api/mail/unread-counts` → `{general, others}`. Mail synced before the split is classified once by `POST /api/mail/backfill-categories` (re-queries Gmail per folder; only touches mail still in Inbox; run once after deploy)
- **Mail conversations** — messages are grouped into one row per conversation (count badge when more than one), e.g. all comments of one GitHub PR. mail-bridge stores a `thread_id` per message: the first `References` entry, else `In-Reply-To`, else the message's own Message-ID (no subject matching, so unrelated mail never merges; threads are per account). Opening a conversation shows its messages oldest first with the newest and unread ones expanded, marks them all read, and translates each message on its own. Star on a row flags the thread (any flagged message → unflag all, else flag the latest). API: `GET /api/mail/threads`, `GET /api/mail/threads/items?account_id&thread_id`, `POST /api/mail/threads/read` and `/flag` (`{account_id, thread_id}` body; the id never goes in the path because Envoy unescapes `%2F` and redirects). Mail synced before threading is grouped after a one-time `POST /internal/backfill-threads` on mail-bridge (header-only IMAP fetch)
- **News** — GeekNews feed reader with article preview expansion and a flag/save-for-later list
- **Guest mode** — routine board (daily + bonus tasks) and calendar work with no account, stored in localStorage; News shows the public feed without flagging. Account-only features (Mail, Assets, Health, Goals, Tasks) are hidden from the nav, and a deep link to one shows a sign-in prompt
- **Push notifications** — Web Push for new email, the daily task digest and finance reminders. Each browser subscribes on its own (iOS needs the home-screen PWA); Settings → Mail lists every subscribed device (`GET /api/push/subscriptions`, labeled from the stored user agent), can remove any of them, and sends a test push to all of them (`POST /api/push/test`)
- **Sync** — sign in to persist data server-side and sync across devices
- **Sign-in** — central SSO at [auth.kevinprk.com](https://auth.kevinprk.com) (client `task`, `admins` group only). The web app exchanges the auth session for a 15-minute access token kept in memory (`GET /api/token?aud=task`); the API verifies it against the auth JWKS (`AUTH_ISSUER`)
- **Assets / Health step-up** — `/api/assets/*` and `/api/health-data/*` need a `step_up` token (`aud=task&step_up=1`), which auth issues only after a passkey check in the last 6 hours (the token itself lives 5 minutes and is re-issued without a prompt inside that window), **and** a username in `STEP_UP_USERS` (default `kevinprk`; anyone else gets 403). One unlock covers both tabs. The tabs are shown only to that account and open without a passkey, with every value masked and **no data request** until the passkey succeeds; Lock, backgrounding the app, 5 minutes idle or token expiry drop the fetched data from memory (unlocking again needs no passkey while the last check is under 6 hours old). Responses are `Cache-Control: no-store`. Passkeys are managed on the auth account page
- **Health** — Apple Health summary (last night's sleep and the last 14 nights first, then 7-day averages, activity rings with steps last, recent runs) from the `health` DB on store-postgres, read as role `health_task`, which can only `SELECT` the one view `hk_task_summary` (no raw samples, no GPS routes). See `~/homeserver/docs/health-dashboard.md`
- **Note** — owner-only group with two tabs, **Notes** (`#/note/notes`) and **Chats** (`#/note/chats[/<conversation id>]`; legacy `#/assistant/<id>` links still open it), `g n`. **Chats** is the chat with the operator's personal profile: asks about routines/tasks/goals/events, spending and assets, the investment portfolio, Apple Health, mail, news and the market, read-only. Same passkey step-up as Assets/Health (it reads both): locked until unlocked, `/api/assistant/*` (SSE chat, conversations, `PATCH /api/assistant/conversations/:id {title?, folder?}`) proxies to the operator with `PERSONAL_TOKEN`. A chat button at the bottom right of every other tab (owner only) opens the same conversation in a small panel (hidden on phones: use the tab; on desktop drag its left edge, top edge or corner to resize it, remembered per browser); both share one state (`lib/assistantStore.ts`) and one lock (`kp-step-up` event). The conversation list is grouped into folders (auto-sorted, movable), its width is draggable and the sidebar can be closed. **Notes** is the owner's note editor, owner-only behind the passkey step-up like Chats (`notes` table, formerly `assistant_memory`; `GET/POST /api/notes[?q=]`, `GET/PUT/DELETE /api/notes/:key`; search, live-preview Markdown editor (`MarkdownEditor.tsx`, CodeMirror 6, lazy-loaded), "Ask about this note"). The assistant searches the notes (`notes_search`, `note_get`) and can only draft changes, shown as an Apply / Dismiss card in Chats. The weekly recap (Sun 20:00 KST) and market check (Mon 21:00 KST) run from ops routines and arrive as conversations plus a push (`POST /internal/push`, bearer `INTERNAL_PUSH_TOKEN`). See `~/homeserver/docs/assistant.md`
- **Retro** — yearly retrospective as a third tab (`Tasks | Goals | Retro`, signed in): Keep / Problem / Try / Action items per year, each entry editable with a checkbox, a comment and a crossed-out state (dropped). Sections are fixed; the layout is 2×2 up to 1500px wide, 4 columns above, 1 column on phones; years are added with the `+` tab. Stored as a goal period with `kind = 'retro'` (`server/retro.js`, `POST /api/goals/periods` with `kind: 'retro'`; entries use the regular goal category/item endpoints)
- **Import / Export** — JSON export of all templates and board settings
- **Dark mode** — manual toggle; PWA install supported with status bar following theme
- **Telemetry** — `server/telemetry.js` serves `http_server_request_duration_seconds{service,route,code}` on `:9467/metrics` (own port, not routed by the gateway; `route` is the Express pattern) and starts a span per request; `server/tracing.js` (loaded with `node --import`) exports spans to the trace gateway when `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is set, with pg and outgoing-HTTP spans, and removes query strings and SQL text before export. `/api/health` is skipped. `auth.verify` times the token check; the signing keys are downloaded before the server listens and refreshed every 30 min (`keepJwksWarm`), so no request waits for `auth.kevinprk.com/keys`. Calls to mail-bridge, finance, operator and ops carry the trace context (undici covers the global `fetch` of `jose`). Admin → Performance → Services shows the graphs and the traces behind a point (`docs/operations/observability.md`, "Traces"). Tests: `node --test test/telemetry.test.js`

## Navigation

Eleven views fold into seven nav groups (left rail on desktop, bottom bar on phones); groups with several views show underline sub-tabs. The phone's bottom bar has four slots for the everyday groups (Overview, Tasks, Calendar, Inbox) and a fifth, **More**, that opens a sheet with the rest (Life, Note, Settings); inside one of them the slot shows that group's name. For an account that sees only one leftover group (a guest: Settings) it stays a plain tab. The group was called Today and then Routine before; its routes (`#/today…`) and the `g t` key are unchanged. The theme toggle sits at the bottom of the rail (on phones it is in Settings).

| Group | Views | Route |
|-------|-------|-------|
| Overview | Overview | `#/overview` |
| Tasks | Tasks, Goals, Retro | `#/today` (Tasks), `#/today/goals`, `#/today/retro` |
| Calendar | Calendar | `#/calendar`, `#/calendar/2026-10` |
| Inbox | Mail, News | `#/inbox/mail`, `#/inbox/news` |
| Life | Assets, Health, Trader (owner only, passkey step-up) | `#/life/assets`, `#/life/health`, `#/life/trader` |
| Assistant | Assistant (owner only, passkey step-up) | `#/assistant`, `#/assistant/<conversation id>` |
| Settings | Settings | `#/settings` |

Every navigation is a history entry, so Back/Forward and reload keep your place. A group with one reachable view (News for guests) is named after it. The selected day tab is not in the URL: it follows the active slot. Legacy links with `?tab=<view>&mail=<id>` (push notifications) still work and are rewritten to the hash form (`src/lib/nav.ts`).

Keyboard (desktop, not while typing): `g` then `o` / `t` / `c` / `i` / `l` / `a` / `s` jumps to Overview / Tasks / Calendar / Inbox / Life / Assistant / Settings, `n` focuses the new-task input, `/` focuses mail search, `[` `]` change month in Calendar, `?` lists them. In the mail list `j` / `k` move the cursor, `Enter` opens, `e` marks read, `s` stars.

## UI building blocks

- `src/colors_and_type.css` is a copy of `~/homeserver/design/colors_and_type.css`; `index.css` only adds a dark lift for `--kp-danger` / `--kp-warning`. No hard-coded colors.
- `components/Icons.tsx` holds every Heroicon (one place, 18px default). `components/Ui.tsx` has `Dialog`, `Meter`, `Loading` (skeleton), `Empty` and the hosts mounted once in `App` (`ToastHost`, `DialogHost`, `LoadingBar`).
- `lib/notify.ts` is callable from anywhere without hooks: `notifyError` (use as `.catch(notifyError)`; logs and shows a toast), `notify`, `confirmDialog`, `promptDialog`. No native `confirm()` / `prompt()`.
- `lib/inflight.ts` counts in-flight API requests per scope (first path segment, e.g. `news`, `mail`) for the thin top progress bar. `LoadingBar` only listens to the scopes of the current tab (`scopesFor` in `lib/nav.ts`), so a refresh of another area never flashes it.
- Mail and News share one split layout (`split-view`, `split-sidebar`, `split-nav`, `split-toolbar` in `index.css`).
- `lib/recurrence.ts` expands recurring calendar events.
- UI text is English throughout (including Assets and Health); holiday names on the calendar stay Korean.
- Empty states use `Empty` (icon, title, hint, optional action) instead of a bare sentence; Assets and Health show one lock card with the passkey button until unlocked. Tasks shows one compact empty state only when nothing at all is planned.
- Deleting a task, bonus task or todo, or hiding a routine for today, shows an Undo toast (`notify(..., { label: 'Undo', run })`). Undo of a delete re-creates the item, so group links and past completions are not restored.
- Phones get a slim top bar (π, current section, theme toggle). Row actions (edit, hide, delete, reorder) show on hover, on keyboard focus, and always on touch devices wider than 600px; on phones they appear after tapping the task text.
- Text is never below 12px (`--kp-text-2xs`); body-level gray text uses `--kp-fg-3`, `--kp-fg-4` is for placeholders, disabled and icon-only controls.
- Calendar week rows share the window height; the number of event lanes per day follows the row height (`maxLanes` in `CalendarView.tsx`), so 5- and 6-week months both fit without scrolling. Assets and Health use two columns from 900px.
- The Mail and News sidebars remember whether you collapsed them (per view, in this browser; phones always start with the overlay closed).

## Startup and sign-in

- `index.html` ships a boot screen (π, "Loading Task…", progress bar, theme set before paint) so the first paint is never blank; after 8 s it offers a Reload button. Fonts load from `<link>` tags there, not CSS `@import`.
- Auth state is `checking | in | out | error` (`App.tsx`). Without the `kp_auth` hint cookie the app starts as a guest at once; with it, a "Signing in…" screen (`StatusScreen`) shows until `/api/token` answers, so guest data never flashes before the account loads. The token request times out after 8 s; an unreachable auth shows Retry (and retries on focus) instead of silently dropping to guest. A real 401 switches to guest through `AUTH_LOST_EVENT`, without a page reload.
- Signed-in board cache: the last server state (settings, templates, todos, calendar events, the last 7 days of daily data) is written to `localStorage` key `task_cache` (`storage.cache` in `src/lib/storage.ts`), owned by the username and cleared on sign-out. On the next open it paints at once while the fresh data loads, so the board opens on today's day with its tasks instead of an empty Monday. With no cache the board shows a skeleton (`boardReady` in `App.tsx`) until templates and today's data arrive. The day (header, chips) starts from the stored rotate time, never from Monday.
- Sign in / Sign out show "Opening sign-in…" / "Signing out…" right away while auth.kevinprk.com loads.
- `public/sw-v2.js` (cache `task-v3`): hashed `/assets/*` are cache-first; page loads are network-first with a 3 s fallback to the cached shell; API calls and cross-origin requests are never touched. nginx serves `sw*.js` with `no-cache`.

## Staging (mock data)

`npm run dev:staging` runs the app with every API call answered in the browser by MSW from
synthetic, typed fixtures (`src/mocks/`); nothing real is touched, a reload resets the data.
`?scenario=empty` shows empty states, `?latency=1500` slows every answer. CI also builds the
`krapi0314/task-web-staging` image, served at `task-staging.kevinprk.com` behind basic auth. A change to a tab updates that tab's fixtures.
Unmocked calls return 501 `not mocked: ...`. Details: `docs/staging.md` in krapie/homeserver.
